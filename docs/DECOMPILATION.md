# Full REA decompilation

The first stage is a complete native decompilation of the client, produced with
REA's Ghidra 12.2 provider. No source tree is written by hand at this stage.

## What was run

For each module:

1. `rea.open_binary(path)` binds the PE and completes Ghidra auto-analysis.
2. `rea.decompile_all(output_directory=..., resume=true, limit=...)` writes one
   `.c` file per function and a manifest.

A long export is split into `limit` batches. `resume: true` continues from the
journal after an interrupted call; verified files are not rewritten.

## Output layout

```
work/decompiled-rea/
  <module>/
    functions/0xADDRESS.c
    decompile-index.json
    decompile-journal.jsonl
  all-functions.tsv
  SUMMARY.md
```

`all-functions.tsv` is generated by `tools/rea_summary.py`; it has one row per
indexed function: module, address, end, name, status, path.

## Current coverage

33 native modules, 79,521 indexed functions: **68,470 written bodies**, 11,049
external (imports/thunks without a body) and **2 failed**, about 618 MB.

The complete protocol path is present: `Tet4.exe` (18,683 bodies), `HgCom3.dll`
(4,219), `HgSock3.dll` (211), `HgModel3.dll` (798), `HgCtr3.dll` (351),
`CDSClientConnector.dll` (888), `TPackClientConnector.dll` (552),
`XInNetwork.dll` (1,731), `XStream.dll` (346).

Failures are not protocol code:

- `HgTool3.dll` `CMyInfoCtrl::OnPaint` at `0x60721170`;
- `IRIA.dll` `FUN_10002430` at `0x10002430`.

Both fail inside Ghidra with "Trying to construct memory range beyond end of
address space"; raising `ghidra.decompile_max_payload_mib` to 1024 MiB did not
help. Keep them as disassembly cases; they are UI/advertising code.

## Not decompiled

- Microsoft runtime and third-party DLLs (`mfc90*`, `msvcr90`, `msvcp90`,
  `msvcm90`, `gdiplus`, `dbghelp`, `fmod`, `ijl15`) are not Hangame code.
- `h-tetra.exe` is .NET. `rea.inspect_managed_members` reports 54 types, 262
  fields, 278 methods and 505 user strings; C# bodies need ILSpy (`ilspycmd`).
  This launcher is separate from the native game.

## Reproduce

The commands are MCP calls, not shell commands. The working output stays in
`work/` (gitignored). A snapshot is committed under `decompiled/` and can be
refreshed with `tools/export_decompilation.sh`; that script stores the full
per-function dump as `decompiled/rea-full.tar.gz` and copies the consolidated
C/H, class headers and RTTI inventory as plain text.

```
tools/rea_summary.py work/decompiled-rea
tools/export_decompilation.sh
```

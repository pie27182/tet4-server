# Scene subsystem

Status of the first reconstruction slice. Addresses are image virtual addresses
in `Tet4.exe` (image base `0x400000`).

## Verified

| Fact | Evidence |
|---|---|
| `DAT_0064EBE8` is the active `CTetSceneManager*` | accessor `0x5810D0`; constructor `0x586D30` stores it |
| `CTetSceneManager` vtable | `0x5FA244`, 36 slots |
| slot 10 (`0x5870C0`) writes `[this+0x8EC]` | disassembly; the crash reads this field |
| Single Mode subclass | `CTetSceneManager_Shadow`, vtable `0x5F9AF4`, 37 slots |
| Shadow constructor | `0x5707A0`, loads `TET4\XML\tet4ui_Shadow.xml` |
| mode factory | `0x4FC280`, cases 1..5 |
| mode dispatcher | `0x4FE660`: `H->5`, `N/Y->1`, `R->3`, `S->4`, non-zero flag->2 |
| room-type key | `k66e`, read by `CChannelLobbyModel::SetRoomInfo` (`HgModel3.dll:0x6090A650`) |
| crash site | `0x4FE2D5`, `mov ecx,[eax+0x70]`, `EAX=0`, scene pointer null |

## Open

- Full field layout of `CTetSceneManager` (base allocation `0x9BC`, Shadow
  allocation `0xA34`). Only `+0x8EC` and the factory fields are known.
- Role names for the 36 base and 37 Shadow vtable slots. The addresses are in
  `metadata/scene_vtable.tsv`; names are not invented.
- MFC/ATL headers are not in the VC9 compiler pack. `CF5GameWnd` methods that use
  MFC types cannot be compiled until those headers are supplied or reconstructed.
- The room-info response that sets `k66e="SHADOW"` and calls slot 10 is still
  missing; that is the current game blocker.

## Artifacts

- `metadata/scene.tsv` — functions, globals and the crash instruction.
- `metadata/scene_vtable.tsv` — generated by `tools/export_vtable.py`.
- `src/scene/scene_manager.cpp` — `GetTetSceneManager` (opcode-shape match) and
  `SceneModeFromChar` (decision slice of `0x4FE660`).
